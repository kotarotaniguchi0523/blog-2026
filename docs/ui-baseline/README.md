## 維持するスタイル

| 部位 | 基準 |
| --- | --- |
| 紹介カード | 角丸20px。余白はPC32px、幅390pxでは20px。青の薄いグラデーション |
| アバター | PC64px角、幅390pxでは56px角。文字を中央配置 |
| 紹介見出し | PC26px、幅390pxでは20px。下余白12px |
| 技術アイコン | 画像32px角、枠48px角。画像余白0、枠の中央に配置 |
| 技術表 | 全セルが横・縦中央。文字・アイコンの位置と行の高さを揃える |
| 作品カード | 角丸16px、PC余白28px。カード間16px |
| ボタン | 高さ40px以上、文字13px、角丸10px、余白8px 14px |

Blog / Scrap のボタンとサイドバーは利用者の追加指定。基準画像にはまだない。
この追加に伴う技術表以下の縦移動は許容する。既存カード内の寸法や装飾は変えない。
Docs7 の検索・Ask AI・読了時間などサービス側のUIは、この自己紹介本文の比較対象に含めない。

同じ文章・幅・ライトテーマで既存13種類の要素の寸法と計算済みスタイルを比較し、
デスクトップとスマートフォンの両方で差分0を確認した。これはピクセル単位の画像差分検査ではない。
ダークテーマでは共通CSSのテーマ変数を維持する。ライトの画像をダークの基準として扱わない。

## Studio で編集した後の確認

1. Studio の Visual で本文・見出し、MDX で表・リンク・属性を編集して保存する。
2. `pnpm docs7:dev` を再起動する。Docs7 0.1.61 はCSS変更の反映に再起動が必要な場合がある。
3. 幅1280pxと390pxで、上記の画像と比較する。
4. アイコンの中央配置、表の中央揃え、紹介・作品カードとボタンの余白を確認する。
5. Blog / Scrap へ移動して戻れることを確認する。

文章量が増えた場合はカードを自然に伸ばす。基準画像の高さに固定して文章を切り詰めない。
Studio の編集用コントロールやHTMLのソース表示は公開UIの基準ではない。
基準の更新は見た目の変更が利用者に指定されたときだけ行い、編集のたびに上書きしない。
